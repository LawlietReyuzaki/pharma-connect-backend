1. PROJECT OVERVIEW
-------------------
PharmaPlatform is a frontend-only React application simulating a SaaS solution for Pharmacy and Clinic management. It demonstrates a modern "Light Mode" aesthetic using a Navy/Royal Blue color palette. The app functions as a Single Page Application (SPA) using React State for routing rather than browser history, making it lightweight and self-contained.

Tech Stack:
- Framework: React 19 (Functional Components + Hooks)
- Language: TypeScript (Strict typing)
- Styling: Tailwind CSS + Custom CSS Variables
- Icons: Lucide React
- Build: Standard HTML/ES Modules (No complex bundler required)

3. FUNCTIONAL COMPONENT LOGIC
-----------------------------
This section details the business logic and state management within key components.

A. App.tsx (Root Router)
------------------------
- Role: Functions as the central router and state manager.
- State: `const [currentPage, setCurrentPage] = useState<Page>('landing');`
- Logic: 
  - Uses a `switch` statement on `currentPage` to conditionally render components (`<Hero />`, `<RegisterPage />`, etc.).
  - Passes the `setCurrentPage` function down to children via the `onNavigate` prop, allowing deep components to trigger page changes.

B. SuperAdminDashboard.tsx (Core Admin Feature)
-----------------------------------------------
- Role: The complex management interface for administrators.
- Props: `onNavigate` (to handle logout or navigation).
- State:
  - `activeTab`: Switches between 'pharmacies' (List View) and 'analytics' (Charts).
  - `selectedPharmacy`: Holds a `PharmacyProfile` object. If not null, the UI renders the Detail View.
  - `searchTerm`: Captures input for filtering the list.
- Key Logic (Memoization):
  - Uses `useMemo` to filter the `SAMPLE_PHARMACIES` array based on `searchTerm`. This optimization ensures the list is only recalculated when the search term changes, not on every render.
- Responsive Behavior:
  - List View: Hides detailed columns (Owner Info, Location) on mobile screens (`hidden md:block`).
  - Mobile Interactions: Clicking a row on mobile opens the Detail View, whereas on desktop it might just expand or select.

C. TrafficAnalysis.tsx (Data Visualization)
-------------------------------------------
- Role: Renders charts and statistics.
- State:
  - `timeRange`: 'today' | '7d' | '30d'.
  - `selectedPharmacyId`: Filters data for a specific entity.
- Logic:
  - Data Generation: Instead of a backend, `useMemo` generates realistic-looking data points based on the selected `timeRange`.
  - SVG Charts: Implements a custom `<SimpleLineChart />` component. It mathematically calculates SVG polygon points from the data array to draw trend lines without needing heavy 3rd-party charting libraries (like Recharts or Chart.js).

D. Header.tsx (Navigation)
--------------------------
- Role: Top navigation bar.
- State: `isOpen` (boolean) for the mobile hamburger menu.
- Logic:
  - Intercepts "Home" link clicks to call `onNavigate('landing')` instead of using standard anchor tags, ensuring SPA behavior.
  - Monitors window resize or scroll (optional enhancements) for sticky behavior.

4. STYLING SYSTEM
-----------------
The project relies on Tailwind CSS with a standardized color palette defined in CSS variables (`index.html`) to ensure consistency between the Tailwind classes and custom styles.

Color Palette:
- Navy 900 (#0f2744): Used for primary headings and strong text.
- Navy 800 (#1e3a5f): Used for primary buttons, active states, and branding.
- Royal Blue (#3B82F6): Used for accents, links, and highlights.
- Slate 50 (#F8FAFC): The main background color for "Light Mode".

Custom Utilities:
- .soft-shadow: `box-shadow: 0 10px 40px -10px rgba(30, 58, 95, 0.08);`
- .card-hover: Adds a lift effect (`translateY(-4px)`) on hover.
