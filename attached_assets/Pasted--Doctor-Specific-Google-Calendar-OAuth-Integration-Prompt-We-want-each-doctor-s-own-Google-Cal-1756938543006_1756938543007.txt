🧑‍⚕️ Doctor-Specific Google Calendar OAuth Integration Prompt

We want each doctor’s own Google Calendar to be used for scheduling appointments. Instead of using a shared service account, we’ll implement OAuth per doctor.

🎯 Goal

Each doctor logs in once with their Google account (via OAuth).

Consent is given to allow the app to manage their calendar (https://www.googleapis.com/auth/calendar).

Tokens are securely stored in the DB (access + refresh).

When a patient books an appointment:

Event is added to the doctor’s Google Calendar.

A Google Meet link is auto-generated by the Calendar API.

The link is saved in the appointments table.

Both doctor and patient see the same functional Meet link.

🔑 Steps to Implement
1. Enable Google Calendar API

Go to Google Cloud Console
.

Create a project → Enable Google Calendar API.

Create OAuth Client ID & Secret (type: Web application).

Add redirect URIs:

https://yourapp.com/auth/google/callback
http://localhost:8000/auth/google/callback   # for local testing

2. Backend Setup

Install dependencies:

pip install google-auth google-auth-oauthlib google-auth-httplib2 google-api-python-client


Configure OAuth Flow:

from google_auth_oauthlib.flow import Flow

flow = Flow.from_client_secrets_file(
    "client_secret.json",
    scopes=["https://www.googleapis.com/auth/calendar"],
    redirect_uri="https://yourapp.com/auth/google/callback"
)
auth_url, state = flow.authorization_url(
    access_type="offline",
    include_granted_scopes="true",
    prompt="consent"
)


Save state to session. Redirect the doctor to auth_url.

3. Callback Route

Google redirects to /auth/google/callback?code=...&state=....

Exchange code for tokens:

flow.fetch_token(authorization_response=request.url)
credentials = flow.credentials


Store in DB:

access_token

refresh_token

expiry

Link these to the doctor’s record in the doctors table.

4. Create Appointment Event

When patient books a slot:

service = build("calendar", "v3", credentials=doctor_credentials)

event = {
    "summary": "Doctor Consultation",
    "description": "Online consultation with patient",
    "start": {"dateTime": "2025-09-01T09:00:00", "timeZone": "Asia/Karachi"},
    "end": {"dateTime": "2025-09-01T09:30:00", "timeZone": "Asia/Karachi"},
    "attendees": [
        {"email": patient_email},
        {"email": doctor_email}
    ],
    "conferenceData": {
        "createRequest": {
            "requestId": f"appt-{appointment_id}",
            "conferenceSolutionKey": {"type": "hangoutsMeet"}
        }
    }
}

event = service.events().insert(
    calendarId="primary",
    body=event,
    conferenceDataVersion=1
).execute()

meet_link = event["hangoutLink"]


Save meet_link in DB.

5. Doctor Dashboard

After logging in via OAuth, doctor’s tokens are saved.

Future events will always use their personal Google Calendar.

Admin can see appointments across doctors.

⚠️ Important Notes

Must request offline access to store refresh token.

Refresh token is only given once per doctor’s consent.

Always check if credentials.expired, refresh using refresh_token.

Store tokens encrypted in DB.

✅ Deliverables

Doctors sign in with Google once.

Tokens linked to their account in DB.

Appointments → automatically create Google Calendar event.

Auto-generate functional Google Meet links per appointment.

Meet link stored and shared with both doctor & patient.
